# 8 October 2026
**Day-15**

* Today I continued my C programming practice with the robot-control exercise in Practice Day-15.c, and I focused on building a small decision-making system that reacts to sensor data and battery level.

* I used an enum named RobotState to represent the robot's possible modes: CHARGING, MOVING, TURNING, and STOPPED. This made the program easier to read and gave a clear structure to the robot's behavior.

* I also used a Robot struct to hold the battery value, sensor array, and current state. The global robot instance helped me simulate a realistic environment where decisions are based on changing conditions.

* I wrote the find_obstacle function to scan the five sensor readings and return the index of the first value below a threshold. This created a clean way to detect where an obstacle was located.

* I then built the decide_state function to evaluate the situation: if the battery is too low, the robot charges; if no obstacle is detected, it keeps moving; if an obstacle is near the front or side areas, it turns; otherwise it stops.

* I also added set_state and perform_action functions so the state update and the action output were separated. This made the logic much clearer and easier to maintain than putting everything inside one main function.

* This exercise reinforced an important idea in programming: good design comes from separating responsibilities. One function detects the condition, another decides the response, and another carries out the action.

* I feel more comfortable using enums, arrays, structs, and function-based state management together. The program is still simple, but it clearly models how a robot can react to real environmental signals in a structured way.

* I want to keep practicing these state-based patterns because they are useful for building more advanced systems where decisions depend on sensor input, timing, and changing conditions.
